分かったこと（どの製品でも先に決める必要があるもの）：
- 文字コードは製品で違う。**UTF-8 を前提にしない**（Shift-JIS の製品がある）。
- 会計ソフト側に**科目・補助科目のマスターが先にある**前提。アプリの科目コードと会計ソフトの科目コードの対応表が要る（§4）。
- 取込後に**伝票枚数・仕訳数が画面に出る**製品がある。照合に使える。
- 取込済みの伝票を**製品側で自動的に重複判定してくれるとは限らない**。二重取込はアプリ側の出力履歴で防ぐ（§6）。

## 4. 対応表と適合例・拒否例

### 4.1 アプリ内のデータ → 取込の項目（製品が確定するまでの暫定）

| 取込の項目（一般） | アプリの出どころ | 現モデルで足りるか |
|---|---|---|
| 伝票日付 | `journal_entries.entry_date`（取引日） | 足りる |
| 伝票番号 | `journal_entries.id`（UUID）は長すぎる。出力ごとに連番（§6 の `export_batches` の行番号）を付ける | 要追加（出力履歴） |
| 借方・貸方の科目コード | `journal_lines.account_id` → `accounts.code` | 足りる（コード体系の対応は §4.2） |
| 借方・貸方の補助科目・部門 | なし | 未対応（使わない運用か、父に確認） |
| 金額（円） | `journal_lines.amount_yen`（借貸一致、整数） | 足りる |
| 税区分・税率・税込／税抜 | `journal_lines.tax_code` 列はあるが**どの処理も入れていない** | **足りない**（§5） |
| 摘要 | `journal_entries.description`・`vendor` | 足りる（桁数の上限は製品で確認） |
| 仕訳の形（単一／振替／複合） | 1仕訳に借貸の行が複数（`line_no`）。いまは1借方・1貸方 | 足りる（複合は未使用） |
| 取消・訂正 | 社長からの戻し → 経理の再確定（同じ仕訳 ID を書き換える） | 要設計（§6） |

### 4.2 科目コードの対応
アプリの `accounts.code` と会計ソフトの科目コードが一致している保証はない。**対応表（アプリの科目 → 会計ソフトの科目コード）を会社設定に持たせる**か、会計ソフト側のコードに合わせてアプリの科目を作る。どちらにするかは未決（§9）。対応がない科目の仕訳は**出力前プレビューで不足として止める**。

### 4.3 架空の適合例・拒否例（形の確認用。実製品の仕様ではない）
次は、アプリが**社内で作る中間表現**の例。製品ごとの書式に直すのは Exporter の仕事。

適合：
```
日付,借方科目コード,借方金額,貸方科目コード,貸方金額,摘要
2026-09-05,5110,150000,1110,150000,〇〇石油（架空）
2026-09-20,5150,50000,1110,50000,消耗品（架空）
```
拒否（プレビューで止める）：
- 借方合計と貸方合計が一致しない
- 科目コードの対応がない科目
- 金額が0以下・桁あふれ
- 日付が会計期間の外
- 未確定（下書き）・社長から戻し中の仕訳
- 税区分が決められない仕訳（§5 で必須とした製品の場合）
- 摘要が製品の桁数を超える（切り詰めずに止める）

## 5. 税区分・税込／税抜・端数
- いまのアプリは**税込の合計金額だけ**を持ち、税率・税区分・インボイス区分・消費税額を持たない（`tax_code` 列は空のまま）。
- 製品が税区分を**必須**にするなら、取込前に分類ごとの既定の税区分（例：燃料＝課税仕入10%）を会社設定に持つか、経理が仕訳で選ぶ画面が要る。**どちらにするかは未決。税区分を AI に決めさせて確定させない**（AI は下書きまで）。
- 端数処理は、金額を税込の整数円で持つ限りアプリ側では出ない。税抜に直す製品では、**製品側の計算と一致するか**を検証用データで確かめる。

## 6. 設計（将来の実装。いまは作らない）

### 6.1 出力履歴（二重取込・再出力・戻しの追跡）
| テーブル | 主な列 |
|---|---|
| `accounting_export_batches` | id・company_id・出力形式（製品・版）・対象期間・出力した人・出力日時・件数・借方合計・貸方合計・ファイルの sha256・状態（作成／取込済みと記録／取り消し） |
| `accounting_export_items` | batch_id・journal_entry_id・伝票番号（バッチ内の連番）・出力時点の金額と日付のハッシュ・出力後に戻されたか |

- ダウンロードは**何度でもできる**が、バッチを作るのは1回の出力ごと。同じ仕訳は「**出力済みのバッチ**」を持つ。
- 取込は会計ソフトで人が行うので、アプリは**取り込んだかを知らない**。経理が「取込済みと記録」を押すまで、出力済みでも未取込として扱い、次回の出力の既定から外すかは**経理が選ぶ**（未決）。
- 既定の出力対象は「**確定**で、まだ取込済みの記録がない仕訳」。出力済み・未記録は「前回の出力に含まれている」と警告する。

### 6.2 戻し・再確定
- 取込済みの仕訳を社長が戻して再確定したとき、**前回出力との差**（金額・日付・科目）を一覧で出す。会計ソフトに取り込み済みの伝票は**アプリから消せない**。経理が会計ソフトで訂正し、アプリは差分の仕訳を「訂正用」として出す（逆仕訳＋新仕訳か、製品の訂正方法に合わせる。製品確定後に決める）。
- 戻し中の仕訳は出力対象から外す。

### 6.3 クラスとルート
- `app/Services/AccountingExportService`：対象の選別（会社から引く）・検証・バッチ作成を `DB::transaction` と `lockForUpdate()` で行う。製品ごとの書式は `app/Services/Accounting/*Exporter`（インターフェースで差し替え）。
- ルート（案）：`/c/{company}/accounting-export`（プレビューと出力）。Livewire でプレビュー、ダウンロードは Controller。
- Policy（案）：`CompanyPolicy::exportAccounting`。**誰に許可するかは人間が決め、`docs/authorization.md` を先に更新する**（案：owner・admin のみ。経理が admin なので、経理が出力できる）。この文書では許可を新設しない。

### 6.4 出力前プレビュー
件数・借方合計・貸方合計・不足項目の一覧・対象外にした件数（下書き・戻し中・判定不能）を出し、**不足があれば出力できない**。不正データは出力せず、どの仕訳のどの項目かを示す。

## 8. 取込不可・不確かな場合の代替
- 税理士への受渡し：Excel の仕訳帳（いまの `WorkbookService` の出力）をそのまま渡す。税理士側のソフトに合わせた取込形式は、税理士に確かめる。
- 残る手作業：会計ソフトへの手入力（月末の転記）。このアプリで減るのは「集める・読む・分類する」まで。
- 「取込は経理が会計ソフトのレイアウトに合わせて貼り付ける」運用（Excel のテンプレートに値だけ貼る）も候補。
