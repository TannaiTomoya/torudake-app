# 認可ルール（正本）

今回の画面遷移修正で使う既存ルールを、要件定義書・詳細設計書 §5・既存の認可テストから整理した。権限を追加する場合は人間が決め、この表を先に更新する。テストの拒否の期待値を先に変えない。

## 共通

- データの所有単位は会社。会社から子データを取得する。
- 未ログインはログイン画面へ。メール未確認はメール確認画面へ。
- 他社・所属なし・無効な所属は404。同じ会社でもロール不足は403。
- 2段階認証がまだの場合は、その会社のホーム（送るだけの人は送信画面）に初期設定カードだけを出す。会社の件数や業務リンクは出さない。ほかの業務画面・画像・ダウンロードは開けない。
- ログイン完了後は `/dashboard` の振り分けを必ず通す。古い `url.intended` を消し、有効な所属のうち最後に開いた会社、なければ最初の会社へ。送るだけは送信画面、ほかのメンバーは会社ホーム。所属がなければ案内画面。
- 個人設定・パスワード再確認・2段階認証設定は、会社の業務画面とは別の認証経路。所属がない人も自身の設定を開ける。
- データ取得はサーバー経由の MySQL。ブラウザーから DB へ直接接続する経路はない（RLS は対象外）。
- 上の条件は画面表示時だけでなく、Livewire の操作・ポーリング通信でも再確認する。所属失効は404、ロール不足は403。メール確認・2段階認証・パスワード再確認の期限が切れたら、対応する認証経路へ戻す。
- 初期設定カードの例外は画面を開くためだけ。認証前の写真追加・送信は `CompanyPolicy::before` で403。ホームの件数は computed なので画面の外から呼べず、2段階認証前は画面にも出さない。送信画面の初期データにも件数を入れない。

- 試算表・開始仕訳（#65）：`CompanyPolicy::viewTrialBalance`・`enterOpeningEntry`。試算表の Excel は、閲覧のみの人も落とせる帳簿（`workbook.xlsx`）には混ぜず、別のファイルにする。開始仕訳は `Company::journalEntries()`（通常の仕訳だけ）から外れるので、仕訳の一覧・詳細・社長の画面・戻す・帳簿の Excel・分析用の書き出しには出ない（開けば404）。
- 取引先への依存の知らせ（#75）：割合を変えるのは `CompanyPolicy::manageConcentrationAlert`（owner だけ）。会社設定を開ける admin には今の数字だけを出し、「変更は社長に依頼してください」と添える。会社設定のほかの欄の保存（`manageSettings`）では、この割合は変わらない。知らせそのもの（上位1社・上位2社の割合）は社長の画面の ⑤ の中に出すので、見られるのは `viewOwner` の人だけ。
- 入金と支払いの予定（#67）：`CompanyPolicy::manageSchedules`（owner・editor だけ。見ることと操作は同じ判定）。画面を開く・予定の保存・済み・済みを戻す・取り消し・取引先の操作のたびに確かめる。予定・取引先・口座は会社から引き、他社は404。
  - 取引先の本当の名前は `business_partners.name` の1か所だけに持つ。監査記録には ID と操作だけを書き、名前は書かない。分析用の書き出し・AI への入力・ログには出さない。個人のお客さんは名前を持たない（取引先なしの入金＝「個人のお客さん」）。
  - 給料は「給料（全員の合計）」の1行だけで、取引先は付けられない（人ごとの名前・金額は持たない）。
  - 済みの予定は直せず、取り消せない（先に「済みを戻す」）。
  - 監査記録（`cash_schedule.*`）には、予定の金額と取引先の ID が残る。監査記録を見る画面・書き出しはまだない。作るときは、予定の分を誰に見せるかをこの表に足してから実装する（admin に見せると、予定の金額が admin に見える）。
  - 給料の行の数は仕組みでは縛っていない（月ごとに入れるため）。同じ日に2行入れることや、取引先の欄に個人の名前を入れることは、画面の注意書きだけで防いでいる。
  - 社長の画面の「入金の遅れ」は、`manageSchedules` が通る人にだけ出す。社長の画面を開ける admin には、件数・合計・取引先の名前のどれも出さない（応答にも入れない）。admin・approver・viewer・送るだけの人が予定の画面と社長の画面を開いても、取引先の名前・金額・給料の合計が応答に入らないことを `CashScheduleTest` で確かめる。
- 通帳の残高（#66）：`CompanyPolicy::enterBankBalance`。画面を開く・保存・取り消しのたびに確かめる。口座と残高は会社から引き、他社は404。入れられる口座は種類が銀行のものだけ。
- 資金繰り表（#68）：`CompanyPolicy::viewCashFlow`（owner・editor だけ。見ることだけ。書き込みはない）。画面を開くたびに確かめる。口座・残高・予定は会社から引き、他社は404。取引先の名前は画面に出さない（金額と日だけ）。
  - 起点の残高は、その口座で今日以前に入れたいちばん新しい残高。残高が1件もなければ見込みは出さず「残高が未入力」（0円とみなさない）。
  - 予定日は動かさない。土日の行に「休日」の印。祝日の表は持たない。土日かどうかは `WeekendCalendar` の1か所だけ。
  - 0円未満の日だけを `ng` と文字で示す。借越の限度額は #63 ができてから。文言は「残高が0円を下回る見込み」（「資金ショート」とは書かない）。
  - 社長の画面の見込みは、`viewCashFlow` が通る人にだけ出す（社長の画面を開ける admin には出さない）。

- 同じ写真の重複通知（#52）：元の原資料を読める人（`viewSource`）にだけ日付と店名を出す。送るだけの人は自分が送った分だけで、他の人が送った写真と同じ中身を送っても、日付・店名・ID・画像の道は返さず「すでに受け付けた写真です」とだけ出す。hash の一致だけで閲覧権限は増えない。会社が違えば独立して受け付ける。
- 送るだけの人の写真は `EvidencePolicy` でも送信者を判定する。他の人の写真は403、他社の写真IDは404。
- 確定は経理の保存だけ。社長は確定後に理由を付けて戻す。確定のまま金額を直接変更しない。
- 履歴からの候補（#54）の「今回も使う」「保留にする」は、新しい権限を作らず `editDraft`（直して確定と同じ）で判定する。候補は欄に入れる・保留にするだけで確定にならず、確定は経理の保存だけ。ライブ画面の候補は表示のみ。候補の根拠は会社の確定履歴だけで、他社の履歴は使わない。

- `/health`（稼働確認）は認証なしで開ける唯一の業務外 URL。応答は `{"app":"torudake","ok":true|false}` だけで、会社・件数・構成・原因は返さない（`no-store`、1分60回まで）。原因は `storage/logs` の警告にだけ書く。

## ホームとナビゲーションの表示

- 表示の優先順位は、開いている会社の有効な所属ロールで決める。表示名は判定に使わない。
- `owner` は社長の画面を主な入口にする。`admin`・`approver`・`editor` は未処理件数と「直して保存」を優先し、0件なら送信を案内する。`viewer` は仕訳一覧、送るだけの人は送信画面。
- デモで「経理担当」として使う `admin` も経理向けホームにする。社長の画面・ライブ・AI記録などを開く権限は上の表どおり保ち、社長の画面は補助リンクでも開ける。
- この表示方針はアクセス許可を与える判定ではない。各リンクと画面・操作は引き続き既存の Policy で判定する。メール確認・2段階認証の前は業務リンクや件数を出さない。

## 帳票の取り込み

owner/admin だけ（`CompanyPolicy::importReports` は社長の画面と同じ判定、`ReportImportTest` で確かめる）。帳票は社長の画面の売上に入るため。approver は版3.0 で承認をやめた役割の名残で、新しい権限は与えない。今のURLは `/c/{company}/reports` の1画面で、詳細設計書の分割画面・顧客別の取り込みはまだない。

保存対象は表示していた取り込みIDに固定し、会社から取得する。IDはクライアントから変更できない。保存時にも `importReports` を再確認し、`review` 状態だけをロックして保存する。対象がなくなったり他の人が先に保存した場合はエラーを表示し、別の取り込みへ切り替えて保存しない。

## 体験・契約・終了（#40）— 決まったが、まだ実装していない

中身と理由は [commercial-pilot.md](commercial-pilot.md)。**ここにあるコマンド・状態は、まだ1つも作っていない。** 実装（#42・#43・#45・#46・#77）のたびに、上の表へ移してテストを足す。

### 決定（2026-11-21、本人）
- 運営者（サービスを運営する人）と、会社の owner・admin は別。会社の owner・admin は、その会社の中だけの役割で、ほかの会社・契約の状態には触れない
- 運営者は本人1人。運営者の役割を DB に作らず、運営者用の画面も作らない。操作はサーバーのコマンドだけ
- **運営者・サポートが帳簿を自由に見られる権限は足さない。** 見るのは、その会社の owner がメンバーとして入れたときだけ、その役割で
- owner は1社に1人以上（複数可）。最後の owner は抜けられない・止められない。会社の解約と、個人のアカウントをやめることは別
- 「見るだけ」（解約・未払い・体験の期限のあと）のあいだ、一覧・詳細を見ることと Excel を落とすことはできる（60日）。役割ごとの可否は上の表のまま

| 操作 | 未ログイン | 運営者（CLI） | owner | admin | そのほか |
|---|---|---|---|---|---|
| 会社を作る・最初の owner を入れる | 不可 | 可 | 不可 | 不可 | 不可 |
| 契約の状態を変える | 不可 | 可 | 不可 | 不可 | 不可 |
| 有料の申込・解約の申し出 | 不可 | 受け付ける | できる | 不可 | 不可 |
| 終わったあとのデータを消す（60日のあと） | 不可 | 実行 | — | 不可 | 不可 |
| owner の交代（#77） | 不可 | owner の依頼で実行。連絡が取れないときは、代表者だと分かる書類を確かめて実行 | 依頼できる | 不可 | 不可 |
| 事例の掲載の同意・取り下げ | 不可 | 不可（記録だけ） | できる | 不可 | 不可 |
| 紹介の記録を見る | 不可 | 可 | 自分が紹介した数だけ | 不可 | 不可 |

- 「見るだけ」のあいだに止めるのは、写真を送る・帳票を取り込む・メンバーを足すことだけ。送ってある下書きの保存と、社長が経理に戻すことは止めない。体験の30枚を使い切ったときに止まるのも、新しく送ることだけ
- 期限より早くデータを消すのは、owner の依頼で運営者が実行する

### 案（まだ決まっていない。この部分を根拠にコードを書かない）
- メンバーを足す・止める・役割を変えるのは、owner の依頼で運営者が実行する。owner が自分で操作できるようにするかは #42 で決める
- 申込の連絡先を見られるのは運営者だけ（#41 で決める）
- 会社が続いているあいだに1人だけやめるときの手順（#42・#77 で決める）
