# 認可ルール（正本）

今回の画面遷移修正で使う既存ルールを、要件定義書・詳細設計書 §5・既存の認可テストから整理した。権限を追加する場合は人間が決め、この表を先に更新する。テストの拒否の期待値を先に変えない。

## 共通

- データの所有単位は会社。会社から子データを取得する。
- 未ログインはログイン画面へ。メール未確認はメール確認画面へ。
- 他社・所属なし・無効な所属は404。同じ会社でもロール不足は403。
- 2段階認証がまだの場合は、その会社のホーム（送るだけの人は送信画面）に初期設定カードだけを出す。会社の件数や業務リンクは出さない。ほかの業務画面・画像・ダウンロードは開けない。
- ログイン完了後は `/dashboard` の振り分けを必ず通す。古い `url.intended` を消し、有効な所属のうち最後に開いた会社、なければ最初の会社へ。送るだけは送信画面、ほかのメンバーは会社ホーム。所属がなければ案内画面。
- 個人設定・パスワード再確認・2段階認証設定は、会社の業務画面とは別の認証経路。所属がない人も自身の設定を開ける。
- データ取得はサーバー経由の MySQL。ブラウザーから DB へ直接接続する経路はない（RLS は対象外）。

## 会社の画面・資料・仕訳

「許可」は上の認証条件を満たした場合。未ログイン・他社の結果は共通方針に従う。

| 操作 | owner | admin | approver | editor | viewer | 送るだけ |
|---|---|---|---|---|---|---|
| 会社ホーム | 許可 | 許可 | 許可 | 許可 | 許可 | 403 |
| 写真を送る | 許可 | 許可 | 許可 | 許可 | 403 | 許可 |
| 原資料の一覧・仕訳の一覧と詳細 | 許可 | 許可 | 許可 | 許可 | 許可 | 403 |
| 写真を開く | 許可 | 許可 | 許可 | 許可 | 許可 | 自分が送ったものだけ |
| 原資料の手直し画面・下書きの確定・対象外 | 許可 | 許可 | 許可 | 許可 | 403 | 403 |
| 社長の画面・経理に戻す・見た | 許可 | 許可 | 403 | 403 | 403 | 403 |
| Excel ダウンロード | 許可 | 許可 | 許可 | 許可 | 許可 | 403 |
| ライブ・AI記録・学習データ出力 | 許可 | 許可 | 403 | 403 | 403 | 403 |
| 会社設定 | 許可 | 許可 | 403 | 403 | 403 | 403 |

- 送るだけの人の写真は `EvidencePolicy` でも送信者を判定する。他の人の写真は403、他社の写真IDは404。
- 確定は経理の保存だけ。社長は確定後に理由を付けて戻す。確定のまま金額を直接変更しない。
- 初期設定カードを出すホーム・送信画面への例外は、既存の T02 とコミット `28b425a` の決定を引き継ぐ。
