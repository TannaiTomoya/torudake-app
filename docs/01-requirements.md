## 1. 目的

家族で経営する小さな会社の、**月末にまとめて書き写す夜をなくす。**

- 現場の人は**撮って送るだけ**（入力欄ゼロ、1件10秒）
- 経理担当は**直すだけ**（AIが下書きを作る）
- 社長は**承認して締めるだけ**（作る人と承認する人を分ける。締めまで「あと何件」かが見える）

決算書・申告は税理士と会計ソフトに任せる。このアプリは、その手前の**一次仕訳を正しく貯める入口**を担う。

## 2. 3段階で進化させる

| 段階 | 計算・判断をするもの | 目的 | 時期 |
|---|---|---|---|
| **1. デモ版（LLM編）** ← 今作る | **Claude（LLM）がすべて行う**：読み取り・分類・仕訳・検算・集計・締めの確認・Excel に載せる数字 | 八幡平市の副市長に「撮って送るだけで帳簿と Excel ができる」を見せる。**LLM の出力と、人が直した結果を学習データとして貯める** | 2026-10-24〜10-25 午前 |
| 2. Python編 | Python の計算ロジック（決まった規則）。LLM は読み取りと候補だけ | 貯めた学習データで間違いの型を調べ、修正と仕訳の流れを規則にする | 次の段階 |
| 3. 実務版 | 規則で承認・締め・取消・権限を守る | 丹内建機の本番業務で使う | Python編のあと |

## 3. 利用者

最初の利用者は**有限会社 丹内建機サービス**（産業用機械の修理・溶接・加工）。会社ごとの値（会社名・決算月・分類・口座）はコードに書かず、会社の設定として持つ。データは会社単位で分け、将来ほかの会社も使えるようにする。

| 人 | ロール | やること | やらないこと |
|---|---|---|---|
| 父（社長） | owner | 承認、月次締め、対象外にする、会社設定。レシートも送れる | 自分で作った仕訳を自分で承認する |
| 母（帳簿） | editor | 撮って送る、AIの下書きを直す、月末に現金を数えて入れる | 承認、対象外、締め |
| 従業員（いれば） | editor＋「送るだけ」 | 撮って送る | 送る以外の画面を見る |
| 作者 | 所属なし | 開発・保守 | 日々の入力・承認、本番データを見る |

- ロールは5つ（owner / admin / approver / editor / viewer）。丹内建機で使うのは owner と editor。
- 自己承認はしない（`allow_self_approval = false`）。
- 会員登録はない。メンバーは owner がコマンドで作る（招待メールは将来）。

## 4. 業務の流れ

```
[現場] 撮って送る → [AI] 読み取り・仕訳の下書き → [経理] 直す（理由を残す）
       → [社長] 承認 → 帳簿 → [社長] 締めナビで0件なら締める → Excel に出す
```

| いつ | 誰 | やること |
|---|---|---|
| レシートをもらったその場 | 社長・経理担当・従業員 | 撮って送る（10秒） |
| 週1回 | 経理担当 | AIの下書きを確かめて直す |
| 週1回（そのあと） | 社長 | 承認。迷うものは差し戻す |
| 月末 | 経理担当 | 手元の現金を数えて残高を入れる |
| 翌月の初め | 社長 | 締めナビが0件なら締め、Excel を出す |

## 5. 機能

**MVP** の列：○＝デモ版で作る（10/25 午前まで）、将来＝Python編・実務版。

### 5.1 デモ版で作るもの
| # | 分類 | 内容 | 使う人 | MVP |
|---|---|---|---|---|
| F01 | 認証 | ログイン・ログアウト・パスワード再設定。メール確認と2段階認証（TOTP＋復旧コード）が済んだ人だけ会社の画面を使える。会員登録はない | 全員 | ○（土台は済み） |
| F02 | 認証 | メンバーの作成：owner がコマンドで作り、パスワード再設定のメールを送る | owner | ○（コマンド） |
| F03 | 権限 | 会社の所属とロールをサーバーで判定する。他社のデータは URL や ID を書き換えても見えない（404） | 全員 | ○ |
| F04 | 集める | **撮って送る**：写真（JPEG・PNG・WebP・HEIC）・PDF、1件10MBまで。入力欄なし（一言メモは任意）。送る画面は6つの状態を描き分ける | editor 以上 | ○ |
| F05 | 集める | 二重を止める：同じ写真（SHA-256一致）は受け付けない。処理中は送るボタンを押せない | システム | ○ |
| F06 | AI | **読み取りと仕訳の下書き**：送った直後に Claude が全文テキスト・日付・店名・合計・分類・借方貸方を作る。各欄に自信度。直した例（最近20件）を毎回渡す | システム | ○ |
| F07 | 直す | 下書きを直す：直した欄と**理由**（読み間違い／分類違い／私的支出／税率違い／その他）と**間違いの型（kernel）**を記録する | editor 以上 | ○ |
| F08 | 一覧 | 原資料の一覧：状態（未処理・下書きあり・仕訳済み・対象外）、送った人、経過日数 | viewer 以上 | ○ |
| F09 | 承認 | **承認**：AIの検算（借方＝貸方）を見て承認する。作った人と別の人だけ。2回押しても1回だけ確定 | owner・admin・approver | ○ |
| F10 | 承認 | 差し戻し（理由つき）・対象外にする（理由つき） | owner・admin・approver | ○ |
| F11 | 締め | **締めナビ**：その月の「あと n 件」（未処理＋下書き）と、AIの月次集計・締めの確認 | viewer 以上 | ○ |
| F12 | 締め | 現金の残高を入れる。0件なら締める（締めた月の日付では下書きも作れない） | editor（残高）・owner（締め） | ○ |
| F13 | 出力 | **Excel**：月ごとの .xlsx（仕訳帳・月次集計＋グラフ・原資料・AIの記録の4シート）。新しいファイルとして出す | viewer 以上 | ○ |
| F14 | 学習 | **AIの記録**：AIの実行回数・そのまま承認された割合・多い直し。学習データを JSONL で書き出す（Python編へ渡す） | owner | ○ |
| F15 | デモ | **ライブ画面**：プロジェクター用。送った写真 → 読み取り → 仕訳 → 承認が流れてくる。直す・承認もこの画面で行う。数字キーで画面を切り替える | owner | ○ |
| F16 | デモ | **デモ再生モード**：API が遅い・失敗したとき、練習で記録した AI の出力を同じ間隔で再生する（画面に「再生」と表示） | システム | ○ |
| F17 | 写真 | **写真の30日削除**：送ってから30日たった写真をストレージから消す。テキスト・ハッシュ・仕訳は残す。監査記録を残す | システム | ○ |
| F18 | 監査 | 送る・読み取り・直す・承認・差し戻し・対象外・締め・出力・写真の削除を記録する | システム | ○ |

### 5.3 作らないもの
- 決算書の作成・申告（税理士と会計ソフトに任せる）
- 写真を正本とする電子保存（電子帳簿保存法のスキャナ保存の要件は満たさない。正本は紙）
- スマホの専用アプリ（ブラウザをホーム画面に追加して使う）
- 家計データ（家計版「猫に小判」とは切り離す）

## 6. データの扱い

| 項目 | 決まり | 状態 |
|---|---|---|
| 写真 | 入力のための一時データ。**30日で自動削除** | 決定 |
| 正本 | **紙の領収書**（原則7年）。保存方法は税理士と確認 | 決定（方法は確認中） |
| アプリに残るもの | 読み取った全文テキスト、写真の SHA-256、仕訳、直した前後・理由・間違いの型、AIの実行記録、監査記録 | 決定 |
| AIへの送信 | 写真を Claude（Anthropic API）に送る。学習には使われない（商用規約）。**デモは架空の領収書**で行う。実在の領収書は社長の同意メモのあと | 決定 |
| 使うモデル | Claude Opus 5.5（`claude-opus-5-5`） | 決定 |
| 金額 | 円の整数（税込） | 決定 |
| 会社の分離 | すべての業務データは会社に属し、他社からは見えない。AIに渡す直した例も会社ごと | 決定 |
| 費用の上限 | 月 $20（$10 で通知）。アプリでも1社1日100回まで | 案（コンソールの設定は本人） |

## 7. 品質と環境の条件

| 項目 | 条件 |
|---|---|
| 画面 | スマホで片手で「撮る → 送る」。ライブ画面はプロジェクター（1920×1080） |
| 文字と色 | 本文16px以上、ライブ画面は32px以上。文字のコントラスト4.5以上、アイコン・枠3.0以上 |
| 言語・時刻 | 日本語、Asia/Tokyo。日付「10月14日(火)」、金額「5,200円」 |
| 速さ | 送ってから完了表示まで3秒以内。AIの読み取りは裏で行い、画面は止めない（30秒で打ち切り） |
| 安全 | HTTPS。2段階認証必須。写真は非公開の場所に置き、権限を確かめる画面からだけ返す |
| 確定の正しさ | 承認・締めは、2回押しても2人同時でも1回だけ |
| 本番 | https://torudake-app.com（ABLENET VPS）。main に push → テスト → 自動デプロイ（反映前に DB をバックアップ） |

## 8. 完成の基準（受け入れ）

| # | 基準 |
|---|---|
| AC01 | 2段階認証を済ませていない人は、会社の画面をどれも開けない |
| AC02 | 会社Aの人が会社Bの URL・ID に書き換えても、原資料・写真・仕訳・締め・Excel はすべて404 |
| AC03 | スマホで撮って送るまでが10秒以内。送った写真が数秒でライブ画面に出る |
| AC04 | 同じ写真を2回送っても1件だけ |
| AC05 | 人が承認するまで、仕訳は承認済みにならない（AIは確定しない） |
| AC06 | 作った人は自分の仕訳を承認できない |
| AC07 | 「あと n 件」＝その月の未処理＋下書き。デモの台本どおり 1 → 2 → 3 → 0 と動く |
| AC08 | Excel が4シートで出る。月次集計にグラフがある |
| AC09 | 直した記録に理由と間違いの型が残り、JSONL で書き出せる |
| AC10 | 30日を過ぎた写真が消え、テキストと仕訳は残り、監査記録がある |
| AC11 | デモの台本（3分）を、本番の torudake-app.com で通せる。API が止まっても再生モードで通せる |
