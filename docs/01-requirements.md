## 1. 目的

家族で経営する小さな会社の、**月末にまとめて書き写す夜をなくす。**

- 現場の人は **撮って送るだけ**（入力欄ゼロ、1件10秒）
- 経理担当は **つないで直すだけ**（通帳の明細は取り込み、写真と突き合わせる）
- 社長は **確かめて締めるだけ**（作る人と承認する人を分け、締めまで「あと何件」かが見える）

決算書・申告は税理士と会計ソフトに任せる。このアプリは、その手前の **一次仕訳を正しく貯める入口** を担う。

### 成功の基準
| 指標 | 目標 | 測り方 |
|---|---|---|
| 経理にかかる月の作業時間 | 2027年9月までに −30%（仮） | 2026年12月に作業ごとの時間を記録（基準値）→ 同じ方法で測り直す |
| 写真が届く割合 | 通帳の明細のうち、写真が付いた割合を毎月見る | 締めナビの数字 |
| 帳簿の正しさ | 承認されていない数字が帳簿に入らない（0件） | 自動テスト |

数値は仮。基準値を測ってから見直す。

## 2. 利用者

最初の利用者は **有限会社 丹内建機サービス**（産業用機械の修理・溶接・加工）。会社ごとの値（会社名・決算月・分類・口座など）はコードに書かず、会社設定として持つ。将来ほかの会社が使えるよう、データは会社単位で分ける。

| 人 | ロール | やること | やらないこと |
|---|---|---|---|
| 父（社長） | owner | 仕訳の承認、月次締め、対象外にする、会社設定、招待。レシートも送れる | 自分で作った仕訳を自分で承認する |
| 母（帳簿） | editor | 撮って送る、通帳の明細を取り込む、仕訳の下書きを作る・直す、月末に現金を数えて入れる | 承認、対象外にする、締め |
| 従業員（いれば） | editor＋「送るだけ」 | 撮って送る | 送る以外の画面を見る |
| 作者 | 所属なし | 開発・保守。データを見るときだけ、父が期限付きで許可 | 日々の入力・承認 |

- ロールは5つ（owner / admin / approver / editor / viewer）。丹内建機で使うのは owner と editor。
- 自己承認はしない（`allow_self_approval = false`）。父が続けられなくなったら、母を approver に上げ、自己承認ありに切り替える（操作と監査記録が残る）。
- 誰でも登録できる会員登録は置かない。招待されたメールアドレスだけが使える。

## 3. 業務の流れ

```
[現場] 撮って送る ─────┐
[経理] 通帳の明細を取り込む ┼→ 原資料（未処理） → 仕訳の下書き → [社長] 承認 → 帳簿 → 月次締め
[経理] 月末に現金を数える ──┘          ↑突き合わせ          ↑直す
                               （日付・金額）   （AIの候補は本番では後から）
```

| いつ | 誰 | やること |
|---|---|---|
| レシートをもらったその場 | 社長・経理担当・従業員 | 撮って送る（10秒） |
| 週1回 | 経理担当 | 通帳の明細を取り込み、写真と突き合わせて下書きを作る・直す |
| 週1回（そのあと） | 社長 | 下書きを確かめて承認。迷うものは差し戻す |
| 月末 | 経理担当 | 手元の現金を数えて残高を入れる |
| 翌月の初め | 社長 | 締めナビで止める項目が0件なら締める |

## 4. 機能

番号は 02・03 とテストから参照する。**MVP** の列：○＝10/24〜10/25午前に本番まで出す、次＝次の週（03 §10）。

### 4.1 基本機能（MVP）
| # | 分類 | 内容 | 使う人 | MVP |
|---|---|---|---|---|
| F01 | 認証 | ログイン・ログアウト・パスワード再設定。メール確認と2段階認証（TOTP＋復旧コード）が済んだ人だけ会社データを使える | 全員 | ○ |
| F02 | 認証 | 招待：owner がメールで招待し、相手がパスワードと2段階認証を設定して参加する。会員登録の画面はない | owner | 次（MVPはコマンドで作る） |
| F03 | 権限 | 会社の所属とロールをサーバーで判定する。他社のデータはIDを書き換えても見えない（404） | 全員 | ○ |
| F04 | 集める | **撮って送る**：写真（JPEG・PNG・WebP・HEIC、PDF）1件10MBまで。入力欄なし（一言メモは任意）。続けて送れる | editor 以上 | ○ |
| F05 | 集める | 二重を止める：同じ写真（SHA-256一致）は受け付けない。処理中は送るボタンを押せない | システム | ○ |
| F06 | 集める | **通帳・カードの明細を取り込む**：ネットバンキングのCSVを口座ごとに取り込み、1行を1件の原資料にする。同じ明細は自動でスキップし、件数を知らせる。明細の残高も記録する | editor 以上 | 次 |
| F07 | 集める | **手持ち現金**：月末に数えた現金の残高を入れる | editor 以上 | ○ |
| F08 | 一覧 | 原資料の一覧：状態（未処理・下書きあり・仕訳済み・対象外）、種類、送った人、経過日数で絞る。写真は権限を確かめてから見せる | viewer 以上 | ○ |
| F09 | 直す | **仕訳の下書き**：原資料から作る。分類を選ぶと勘定科目が決まる。写真と明細を日付・金額で突き合わせる候補を出す | editor 以上 | ○（突き合わせは次） |
| F10 | 直す | 重複の警告：同じ日付・金額・取引先の承認済み仕訳があれば知らせる（止めない） | システム | ○ |
| F11 | 承認 | **承認**：借方・貸方の合計が一致し、締めていない期間で、作った人と別の人なら承認できる。2回押しても1回だけ確定 | owner・admin・approver | ○ |
| F12 | 承認 | 差し戻し：承認者が理由を付けて下書きを戻す | 承認できる人 | ○ |
| F13 | 直す | **取消**：承認済みの仕訳は書き換えない。反対の仕訳（取消）と正しい仕訳で直し、履歴が残る | 承認できる人 | 次 |
| F14 | 直す | 対象外にする：私的な支出などを、理由を付けて仕訳しない | owner・admin・approver | ○ |
| F15 | 締め | **締めナビ**：月ごとに、未処理の原資料・下書き・写真のない明細・口座と現金の残高の差・自己承認の可否を「あと何件」で出す | viewer 以上 | ○ |
| F16 | 締め | **月次締め**：止める項目（下書き・貸借不一致）が0件なら締める。締めた期間の日付では、下書きも保存できない。締めたあとに届いた原資料は「遅れて届いた」印を付けて翌月で処理 | owner | ○ |
| F17 | 写真 | **写真の30日削除**：送ってから30日たった写真をストレージから消す。読み取ったテキスト・ハッシュ・仕訳は残す。消したことを監査記録に残す | システム | ○ |
| F18 | 監査 | 送る・取り込む・下書き・承認・差し戻し・取消・対象外・締め・設定変更・写真削除を監査記録に残す | システム | ○ |
| F19 | 設定 | 会社設定：会社名、決算月、記帳開始日、分類と勘定科目のつながり、口座（銀行・カード・現金）、自己承認の可否、メンバーとロール、「送るだけ」の印 | owner（admin） | ○（追加・変更の画面は一部） |
| F20 | 保守 | サポート許可：owner が作者に、期限と理由を付けてデータを見る許可を出す・取り消す | owner | 次 |

### 4.2 AIの読み取り（テスト環境で先に試す）
| # | 内容 | 時期 |
|---|---|---|
| A01 | 写真から日付・合計金額・店名・分類の候補と、読み取った全文のテキストを Claude で作る。候補は下書きの初期値まで。自信の低い欄に印を付ける | 次の週以降 |
| A02 | 人が直した前と後、理由（読み間違い／分類違い／私的支出／税率違い／その他）を会社ごとに貯め、次の読み取りに例として渡す | 次の週以降 |
| A03 | 同じ直しが続いたら分類のルール案を出し、人が承認したら有効にする | 拡張 |
| A04 | 承認済みの間違いに対し、「取消＋正しい仕訳」の案を作る（承認は人） | 拡張 |

**本番では最初はAIを使わない。** テスト環境で、個人情報を消した領収書100枚の項目ごとの正解率を測り、合格した項目だけ本番で下書きの初期値にする（会社設定で項目ごとに有効化）。

### 4.3 拡張の候補（MVPのあと）
| # | 内容 |
|---|---|
| E01 | 試算表・損益計算書・貸借対照表（承認済みの仕訳だけから作る） |
| E02 | 税理士・会計ソフト向けの出力（CSV。形は税理士と決める） |
| E03 | 未処理の通知メール（週1回のまとめ） |
| E04 | よく使う「取引先＋分類」の候補 |

### 4.4 作らないもの
- 決算書の作成・申告（税理士と会計ソフトに任せる）
- 給与計算・請求書の発行
- 写真を正本とする電子保存（電子帳簿保存法のスキャナ保存の要件は満たさない。正本は紙）
- 通帳・カードの写真の読み取り（明細データで取り込む）
- スマホの専用アプリ（ブラウザをホーム画面に追加して使う）
- 家計データの取り込み（家計版「猫に小判」とは切り離す）

## 5. データの扱い

| 項目 | 決まり | 状態 |
|---|---|---|
| 写真 | 入力のための一時データ。**30日で自動削除**。バックアップも30日で消える設定にする | 決定（2026-10-23） |
| 正本 | **紙の領収書**。原則7年保存。保存方法は税理士と確認する | 決定（方法は確認中） |
| アプリに残るもの | 読み取った全文のテキスト、写真のハッシュ（SHA-256）、仕訳、直した前後と理由、監査記録 | 決定 |
| AIへの送信 | 写真を Claude（Anthropic API）へ送る。まず自社だけ、社長の同意をメモで残して使う。他社に広げるときはその会社の同意を取る | 決定 |
| 使うモデル | Claude Opus 5.5（`claude-opus-5-5`） | 決定 |
| 金額 | 円の整数（税込）。小数は使わない | 決定 |
| 会社の分離 | すべての業務データは会社に属し、他社からは見えない。AIに渡す例も会社ごと | 決定 |

## 6. 品質と環境の条件

| 項目 | 条件 |
|---|---|
| 画面 | スマホのブラウザで片手で「撮る → 送る」。経理・承認の画面はスマホとPCの両方 |
| 言語・時刻 | 日本語、Asia/Tokyo。日付は「10月14日(火)」、金額は「5,200円」 |
| 速さ | 送るボタンを押してから完了表示まで3秒以内（4G回線、5MBの写真） |
| 安全 | HTTPS。2段階認証必須。写真は非公開の保存先に置き、権限を確かめる画面からだけ見せる |
| 確定の正しさ | 承認・取消・締めは、2回押しても2人同時でも1回だけ |
| 環境 | 開発・テスト（ステージング）・本番の3つ。本番の実データはテスト環境に持ち込まない |
| 戻せること | 本番に出す前に毎回バックアップ。戻す手順を runbook に書き、テスト環境で一度練習する |

## 7. 完成の基準（受け入れ）

| # | 基準 |
|---|---|
| AC01 | 2段階認証を済ませていない人は、会社の画面をどれも開けない |
| AC02 | 会社Aの人が会社BのIDに書き換えても、原資料・写真・仕訳・明細はすべて404 |
| AC03 | 撮って送ってから、原資料の一覧に出るまでが1件10秒以内の操作で済む |
| AC04 | 同じ写真・同じ明細・同じ送信の再送で、データが2件にならない |
| AC05 | 承認されていない仕訳は、帳簿・締めナビの残高・集計に入らない |
| AC06 | 承認済みの仕訳は書き換え・削除できず、取消の仕訳で直すと履歴が残る |
| AC07 | 作った人は自分の仕訳を承認できない（`allow_self_approval=false` のとき） |
| AC08 | 締めた月の日付では下書きも保存できない。締めナビの件数と、締めを止める条件が一致する |
| AC09 | 30日を過ぎた写真はストレージから消え、テキストと仕訳は残り、監査記録がある |
| AC10 | テスト環境で「更新 → バックアップ → 戻す」を手順書どおりに一度通せる |
